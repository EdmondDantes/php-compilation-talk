Что скомпилировалось

$ limelight jit --trace public/index.php
T3 Illuminate\Pipeline\pipe hot: 8 901
T2 App\Repository::hydrate hot: 1 240
T1 App\Support\Str::snake hot: 1 018

Тир, символ и счётчик — по каждому решению компилятора. Холодная загрузка приложения остаётся в интерпретаторе: компилировать её нечего.

02 · Пайплайн компиляции

Чего компилятор не знает

  1. 01Ссылки: &$x меняет владельца значения и ломает предположение о типе.guard
  2. 02Магия: __get и __call меняют форму объекта на ходу.форма объекта
  3. 03eval и include: код появляется после того, как трасса скомпилирована.новый байткод
  4. 04Guard не сошёлся — исполнение возвращается в интерпретатор.деоптимизация

04

Ландшафт

PHP компилировали десять с лишним лет. Почти каждый проект выбирал между совместимостью и скоростью — и почти каждый выбрал скорость.

04 · Ландшафт

Карта подходов

AOT → свой бинарник

KPHP, Swoole Compiler, manticore, phprs. Типы решаются на компиляции — значит, динамику приходится запрещать.

JIT → свой процесс

JIT в php-src, HHVM, Limelight. Компилируется то, что реально горячее; за это платят прогревом.

AOT → чужая VM

PeachPie (CIL), JPHP (JVM), Zephir. Выход — байткод, а не машинный код.

JIT чужой VM

PeachPie отдаёт финальную компиляцию .NET: своего оптимизатора нет.

04 · Ландшафт · AOT

KPHP

Транспилятор PHP в C++ с выводом типов по всей программе. Не JIT: типы известны на компиляции, фазы прогрева нет.

github.com/VKCOM/kphp

Цена скорости — переписать код под систему типов компилятора: существующий проект почти никогда не собирается с первого раза.

МодельPHP → C++ → бинарник с HTTP-сервером внутри
Выигрыш3–10× на коде под строгие типы
ОграниченияНет генераторов, анонимных классов, вызова по имени
СтатусVK.com, открыт в конце 2020, GPLv3
04 · Ландшафт · AOT в чужую VM

PeachPie

Компилирует PHP в CIL и запускает на .NET. Построен на Roslyn, наследник Phalanger.

github.com/peachpiecompiler/peachpie

Ценен не скоростью, а двусторонней совместимостью: части приложения на PHP и на C# живут в одной сборке.

МодельPHP → CIL, финальную компиляцию делает JIT самой .NET
ВыходСборки .NET; PHP и C# в одном проекте
СовместимостьСвой рантайм, повторяющий поведение PHP
СтатусПроект .NET Foundation с 2017, Apache 2.0
04 · Ландшафт · AOT

Swoole Compiler

Коммерческий AOT: компилирует опкоды в нативные исполняемые файлы или динамические библиотеки и попутно шифрует исходный код.

business.swoole.com/compiler

Считается только на счётной нагрузке и внутри собственной модели исполнения Swoole; веб-фреймворки вне зоны поддержки.

МодельБайткод → нативный бинарник, Windows / Linux / macOS
Заявка вендораДо 150× на вычислительной нагрузке
ОграниченияНет yield: Laravel, Symfony и WordPress не запускаются
Побочная цельОбфускация и защита исходников, а не только скорость
04 · Ландшафт · AOT

manticore

AOT-компилятор PHP, написанный на самом PHP: через LLVM IR в самостоятельный бинарник без рантайма PHP.

github.com/manticorephp/compiler

PHP как язык системного программирования: на выходе бинарник, которому нужен только libc.

МодельPHP → LLVM IR → arm64 / x86_64, из зависимостей только libc
СамохостингКомпилирует сам себя до побайтово совпадающей точки
ПокрытиеШирокое подмножество PHP 8.5: классы, трейты, энумы, замыкания
РасширенияБиндинги нативных библиотек по манифесту, MVP
04 · Ландшафт · AOT

phprs

Синтаксис PHP с семантикой Rust: владение вместо сборки мусора, компиляция через Cranelift.

github.com/neokofg/phprs

Убрать из PHP всё, что мешает компилятору, можно — но на выходе получается другой язык.

МодельСвой лексер, парсер, вывод типов, borrow checker, кодоген на Cranelift
ПамятьВладение и перемещение значений, сборщика мусора нет
РантаймСобственный: строки, массивы, JSON, HTTP, SIMD
Совместимость$s2 = $s перемещает значение — старый код так не работает
04 · Ландшафт · JIT

HHVM и Hack

HipHop компилировал PHP в C++, HHVM заменил его виртуальной машиной с JIT — а затем поддержку PHP из HHVM убрали.

github.com/facebook/hhvm

Развилка, на которой стоит каждый такой проект: остаться совместимым с PHP или стать отдельным языком. Здесь выбрали второе.

МодельСначала AOT в C++, затем JIT-виртуальная машина
СовместимостьPHP поддерживался до 3.24, дальше только Hack
ПричинаЯзык разошёлся с PHP: типы, семантика, стандартная библиотека
УрокСовместимость — это работа, которую надо делать постоянно
04 · Ландшафт

Что не дожило

  1. 01Phalanger — PHP в .NET, предшественник PeachPie.продолжен
  2. 02Roadsend и Raven — PHP через LLVM; переписывание на C++ не дошло до релиза.заброшен
  3. 03Recki-CT — компилятор подмножества PHP, написанный на PHP.эксперимент
  4. 04php-compiler — JIT и AOT через FFI и LLVM, тот же автор.эксперимент
  5. 05Tagua VM — виртуальная машина PHP на Rust и LLVM.заброшен
  6. 06JPHP — PHP на JVM: чужая VM, чужая экосистема.нишевый

05 · Цифры и выводы

Когда компиляция окупается

CLI-скрипт

Процесс живёт секунды — компилятор не успевает прогреться.

Очередь и крон

Долго, но время уходит в базу — выигрыш в памяти, не в CPU.

Веб-запрос на FPM

Прогрев на каждый процесс: спасает только кэш трасс.

Долгоживущий воркер

Горячий код остаётся горячим — компиляция окупается.
